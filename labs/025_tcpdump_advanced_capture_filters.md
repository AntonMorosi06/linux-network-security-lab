# Lab 025 — tcpdump Advanced Capture Filters

## Objective

The objective of this lab is to practice safe packet capture with `tcpdump` using a narrow loopback filter.

The lab starts a local HTTP service bound to `127.0.0.1:8090`, generates local requests, captures only loopback packets for that local port, and creates a defensive report.

This lab does not capture third-party traffic, Wi-Fi traffic or private user traffic.

## Safety boundary

Allowed:

```text
127.0.0.1
loopback interface
local service created by this lab
short packet-count capture
local PCAP file
local report
```

Not allowed:

```text
third-party networks
Wi-Fi traffic from real users
private browsing capture
credential capture
public network monitoring
publishing sensitive PCAP files
```

## Step 1 — Check requirements

```bash
./scripts/tcpdump_lab025_check_requirements.sh
```

Expected output:

```text
[OK] python3 found
[OK] curl found
[OK] tcpdump found
```

If `tcpdump` is missing, the script explains how to install it.

## Step 2 — Capture loopback traffic

```bash
./scripts/tcpdump_lab025_capture_loopback.sh
```

The script starts a local HTTP service on:

```text
http://127.0.0.1:8090
```

Then it attempts a short tcpdump capture using a filter scoped to:

```text
tcp port 8090 and host 127.0.0.1
```

On some systems, packet capture requires elevated privileges. If the capture cannot run because permissions are missing, the script exits safely and explains the issue.

## Step 3 — Create report

```bash
./scripts/tcpdump_lab025_create_report.sh
```

Expected output:

```text
[OK] Report created:
~/linux_lab/reports/lab025_tcpdump_advanced_capture_filters_YYYYMMDD_HHMMSS.txt
```

## Safe tcpdump commands

Linux:

```bash
sudo tcpdump -i lo -nn -c 10 'tcp port 8090 and host 127.0.0.1'
```

macOS:

```bash
sudo tcpdump -i lo0 -nn -c 10 'tcp port 8090 and host 127.0.0.1'
```

Read local PCAP:

```bash
tcpdump -nn -r data/lab025/lab025_loopback_http.pcap
```

```text
The capture contains local TCP packets generated by requests to 127.0.0.1:8090.
The filter limited scope to loopback traffic.
No third-party traffic was captured.
```

## Common issues

### Permission denied

Packet capture often requires elevated privileges.

Use only on your own machine:

```bash
sudo ./scripts/tcpdump_lab025_capture_loopback.sh
```

or read the generated report and document that capture was blocked by permissions.

### Wrong loopback interface

The script automatically uses:

```text
lo0 on macOS
lo on Linux
```

If your system uses a different interface, update the script locally and document it in the report.

### Port already in use

If port `8090` is busy, stop the other service or change the port in the script.

## Final conclusion

The core chain is:

```text
local service
-> local requests
-> narrow tcpdump filter
-> local PCAP
-> defensive report
```

A safe packet capture starts with a narrow scope and ends with a privacy review.
