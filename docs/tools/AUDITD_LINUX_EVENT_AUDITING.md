# auditd and Linux Event Auditing

## Purpose

This document introduces `auditd`, the Linux Audit daemon, from a defensive event-auditing perspective.

`auditd` can record security-relevant events such as file access, command execution, permission changes, authentication-related activity and administrative actions. Because audit configuration affects the system and may produce sensitive logs, this repository treats auditd carefully.

Lab 028 performs read-only inspection, dry-run rule generation and synthetic event documentation. It does not install auditd, start services, load rules or modify `/etc/audit`.

## Safety boundary

Allowed:

```text
checking whether audit tools exist
read-only status inspection
dry-run audit rule examples
synthetic event generation
report writing
conceptual mapping between event, rule and finding
```

Not allowed:

```text
modifying /etc/audit
loading audit rules automatically
restarting auditd
collecting private user activity
publishing real audit logs without review
monitoring users without authorization
```

## Main tools

| Tool | Purpose |
|---|---|
| `auditd` | Linux Audit daemon |
| `auditctl` | control and inspect audit rules/status |
| `ausearch` | search audit logs |
| `aureport` | summarize audit logs |
| `journalctl` | inspect systemd logs, sometimes useful around audit services |
| `systemctl` | inspect service status on systemd systems |

## Common audit concepts

| Concept | Meaning |
|---|---|
| audit rule | instruction describing what the audit system should watch |
| watch rule | rule watching a file or directory path |
| syscall rule | rule watching specific kernel-level operations |
| key | label attached to events so they can be searched later |
| event | audit record generated by a matching rule |
| ausearch | command used to search audit events |
| aureport | command used to summarize audit activity |

## Safe example rules

These examples are generated as dry-run documentation only:

```text
-w /etc/passwd -p wa -k identity_changes
-w /etc/shadow -p wa -k credential_store_changes
-w /etc/sudoers -p wa -k privilege_policy_changes
-w /var/log/auth.log -p r -k auth_log_read
-a always,exit -F arch=b64 -S execve -k command_execution
```

Important: do not load these blindly. Audit rules can generate sensitive logs and high event volume.

## Defensive interpretation

A useful audit report should answer:

```text
What asset is being watched?
Why is this asset security-relevant?
What event would the rule detect?
What key labels the event?
What privacy risk does the event have?
What should be reviewed before publishing logs?
```

## Privacy warning

Audit logs may contain:

```text
usernames
commands
file paths
process arguments
hostnames
session data
authentication-related information
administrative actions
```

Do not publish raw audit logs without review.

## macOS note

`auditd` in this repository refers primarily to Linux auditd. macOS has different auditing and logging systems. On macOS, this lab may only produce requirement checks, dry-run rules and synthetic examples.

## Final rule

Audit data is powerful and sensitive. Collect the minimum event data needed, document authorization and review before publication.
