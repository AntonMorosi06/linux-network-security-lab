# Wireshark and TShark Packet Analysis

## Purpose

This document introduces Wireshark and TShark from a defensive, local and privacy-safe perspective.

Wireshark is a graphical packet analysis tool. TShark is the command-line packet analysis tool from the Wireshark ecosystem. In this repository, packet analysis is practiced with synthetic or explicitly authorized captures only.

## Safety boundary

Allowed:

```text
reading synthetic PCAP files
reading sample training PCAP files
analyzing traffic generated by a local lab
filtering DNS/HTTP/TCP/UDP fields
writing local reports
```

Not allowed:

```text
capturing third-party traffic
publishing private user traffic
monitoring networks without permission
collecting credentials
publishing real IP/MAC/SSID data without review
```

## Why PCAP-first is safer

A PCAP file is a saved packet capture. Starting from a synthetic PCAP is safer than live capture because:

```text
the traffic is controlled
no private users are involved
the data can be regenerated
the output is reproducible
the lab remains safe for GitHub
```

## Core TShark concepts

| Concept | Meaning |
|---|---|
| `-r file.pcap` | read packets from a capture file |
| `-Y "filter"` | apply a display filter |
| `-T fields` | print selected fields |
| `-e field.name` | choose a field to print |
| `dns` | filter DNS packets |
| `http` | filter HTTP packets |
| `tcp` | filter TCP packets |
| `udp` | filter UDP packets |
| `frame.number` | packet number in the capture |

## Safe example commands

```bash
tshark -r data/lab022/local_http_dns_sample.pcap
tshark -r data/lab022/local_http_dns_sample.pcap -Y "dns"
tshark -r data/lab022/local_http_dns_sample.pcap -Y "http"
tshark -r data/lab022/local_http_dns_sample.pcap -T fields -e frame.number -e ip.src -e ip.dst -e _ws.col.Protocol -e _ws.col.Info
```

These commands read a local synthetic file. They do not capture live traffic.

## Defensive interpretation

Packet analysis helps answer:

```text
Which hosts are communicating?
Which protocols appear?
Which destination ports are used?
Is traffic expected or unusual?
Are there repeated errors?
Does the evidence match the timeline?
```

## Publication warning

Before publishing packet analysis output, check that it does not contain:

```text
private IPs from real networks
MAC addresses from real devices
hostnames from private systems
cookies
tokens
credentials
real DNS queries from personal browsing
Wi-Fi SSIDs or BSSIDs from nearby networks
```

## Final note

This repository uses packet analysis to teach defensive reasoning. It must not be used for unauthorized traffic capture.
